# 文章风格分析框架（通用版）

> 本框架适用于**任何**有作者署名/账号归属的中长文样本，不限平台。
>
> 核心架构：**通用 5 维（任何文章都跑）+ 场景增量维度（按平台/体裁动态启用）**
>
> 分析的最终产物有两份：
> - `[作者名]风格分析报告.md`（给人看）
> - `style_profile.yaml`（给机器看，schema 见 `style-profile-schema.md`）

## 1. 素材处理规范

### 1.1 输入

样本统一从 `samples_normalized/` 目录读取，格式见 `sample-format.md`。所有原始素材（md/txt/html/docx/pdf）由 `scripts/normalize_samples.py` 预先转换。

### 1.2 最低样本量

| 分析目标 | 最低样本 | 推荐样本 |
|----------|----------|----------|
| 快速风格速写 | 5 篇 | — |
| 标准风格分析 | 10 篇 | 15-20 篇 |
| 深度拆解 + 生成写作 skill | 15 篇 | 30-40 篇 |
| 多账号对比 | 每账号 8 篇 | 每账号 15 篇 |

### 1.3 取样策略

确保样本覆盖以下变量：
- **类型多样**：至少覆盖 3 种以上文章类型（频道偏好 vs 风格本身要区分开）
- **时间跨度**：最好跨越 1 个月以上（看风格一致性 / 是否有演化）
- **长短均有**：包含该作者最长和最短的文章
- **热度差异**：既有"代表作"也有普通文章

### 1.4 精读选样

从全量样本中选 8-12 篇精读：
1. 每个主要类型至少选 1 篇
2. 优先选标题最有特色的（标题是风格浓缩）
3. 选 1-2 篇"非典型"文章（看作者在不同语境下是否保持风格）
4. 如果作者有"团队投稿 vs 自采稿"区分，两者都选

### 1.5 阅读方法

**第一遍（浏览扫描）**：只看标题、第一段、小标题、结尾——5 分钟/篇

**第二遍（精读标注）**：逐段阅读，记录以下内容：
- 力量动词（→ 进 `power_verbs`）
- 极短句（→ 进 `rhythm.short_paragraph_rate` 统计）
- 口头禅 / 惯用表达（→ 进 `signature_phrases`）
- 引用 / 归因方式（→ 进 `language_style` 或场景增量）
- 语气切换点（→ 进 `tone_palette.tone_transitions`）
- 标点的"非常规用法"（→ 进 `punctuation_rules`）

## 2. 场景识别

**这是分析的第 0 步**：先判断样本属于什么场景，决定启用哪些增量维度。

### 2.1 识别依据

从样本 frontmatter 的 `platform` 字段统计；如果不可信或缺失，从正文特征反推：

| 特征 | 暗示的场景 |
|------|-----------|
| 文末有"长按关注""一键三连""微信号 xxx" | 公众号 |
| 开头是问题、答主介绍、有"匿名"标识 | 知乎 |
| 大量 emoji、标签 `#xxx`、极短行、口语化 | 小红书 |
| 推文串编号 `1/`, `2/`, `3/`，单段极短 | Twitter / X |
| 摘要 / 关键词 / 引言 / 参考文献结构 | 学术 |
| 长段、规整、无 emoji、有论证标志词 | 严肃博客 / 新闻 |
| 意象密集、感官词丰富、第一人称多 | 个人散文 |

### 2.2 多场景混合

如果一个作者在多个平台都有样本（例如：公众号 + 知乎 + Twitter），分两步：
1. 通用 5 维**合并所有样本**统计（这是该作者的"底色"）
2. 场景增量维度**分平台**填充（这是"同一个人在不同平台的适配"）

最终 `style_profile.yaml` 的 `scene_extras` 下会有多个 key 并存。

### 2.3 场景识别失败

如果样本类型混乱、跨度过大、看不出主导场景，**只填通用 5 维**，`scene_extras` 留空。这种情况下生成的写作 skill 也只学"语言肌理"，不学"平台适配"。

## 3. 通用五维分析

任何文章都跑这 5 维。每个维度的产出**最终要落到** `style_profile.yaml` 对应字段（schema 见 `style-profile-schema.md`）。

### 维度一：标题术 → `title_craft`

#### 需要采集的数据点

| 指标 | 采集方法 | 进入档案的字段 |
|------|----------|---------------|
| 标题字数 | 统计每个标题字符数，取平均和分布 | `avg_length`, `length_range` |
| 信息层数 | 每个标题包含几个独立信息单元 | `info_density` |
| 标点类型 | 各标点出现频率 | `punctuation_usage` |
| 数字使用率 | 含精确数字的标题占比 | `number_usage_rate` |
| 人名 / 品牌出现率 | 含命名实体的标题占比 | `named_entity_rate` |
| 情绪词 | 标题中所有情绪词按频率排序 | `emotion_words` |
| 对立结构 | 是否使用"从X到Y""别人X，它偏Y"式对立 | 写入 `notes` |

#### 标题公式提炼方法

将所有标题的结构抽象化，归纳为可填空的模板（3-7 条），每条必须配一个真实样本例：

- `[主体] + [动作] + [结果/数据]` → "OpenAI 收购 Astral，Python 包管理神器 uv 现在姓 O 了"
- `[反常识事实]，[情绪反应]！` → "性能超 GPT-5，完全端侧运行！"
- `[主体A] vs [主体B]，[悬念]` → 对立结构

写入 `title_craft.formulas`。

### 维度二：开篇手法 → `opening_craft`

#### 钩子类型库

| 钩子类型 | 特征 | 适用场景 |
|----------|------|----------|
| 震惊式 | 感叹号 + 加粗核心事实 | 突发新闻 |
| 立场式 | 第一句就表态 / 情绪 | 争议事件 |
| 反常识式 | 反直觉的事实陈述 | 人物 / 深度 |
| 痛点式 | "苦于X？"式提问 | 产品 / 技术 |
| 社区式 | 用昵称打招呼 | 系列栏目 / 社群 |
| 引语式 | 直接引用名人原话 | 访谈 / 人物 |
| 数据式 | 用一个惊人数字开场 | 行业 / 财经 |
| 场景式 | 描述一个具体场景 | 深度长文 / 故事 / 散文 |

统计每种钩子类型出现的次数和占比 → `hook_distribution`。

对前 3 名钩子（`preferred_hooks`），每个写出"可复用模板 + 真实样本例"，进入 `hook_templates`。

#### 开篇节奏测量

- 第一句话字数 → `first_sentence_avg_chars`
- 前 3 句话总字数
- 前 3 句话完成了什么任务（给信息 / 造情绪 / 设悬念）
- 背景信息出现在第几段 → `background_placement`（early / late）

#### 人称偏好

统计开篇 200 字内"你/我/我们"出现密度 → `pronoun_usage`。

### 维度三：段落节奏与结构 → `rhythm`

#### 节奏序列标注

取 3-5 篇文章，对每一段标注类型：
- **L** = 信息段（2-3 句话，给事实）
- **S** = 极短段（1 句话 / 几个字，给情绪或转折）
- **I** = 图片 / 截图
- **Q** = 引用块
- **H** = 小标题

序列示例：
```
L-L-S-I-L-S-L-L-I-S-L-H-L-L-S-I-L-Q-S-L
```

寻找重复模式 → `rhythm_pattern`，加自然语言注释 → `rhythm_pattern_notes`。

#### 段落长度统计

- 每段平均句数 → `avg_sentences_per_paragraph`
- 极短段（≤8 字独立成段）出现频率 → `short_paragraph_rate`
- 最长段和最短段的落差（写入 `notes`）

#### 小标题

- 是否使用 → `uses_subheadings`
- 风格特征（信息密度 / 是否带情绪）→ `subheading_style`
- 一个典型例子 → `subheading_style.example`

#### 图片节奏

每隔多少段出现一张图 → `image_frequency`（自然语言，如 "every 4-5 paragraphs"）。

#### 段间过渡

记录主要过渡方式 → `transition_style`。

### 维度四：语言风格 → `language_style`

这是最核心的维度，需要分多个子层面拆解。

#### 4.1 动词采集 → `power_verbs`

精读时逐篇记录所有**非通用**动词。"非通用"指：能被替换成更平淡的中性词的、带情绪倾向的动词。

| 原文动词 | 出现次数 | 替代了什么中性词 | 情绪强度(1-5) | 情感极性 | 示例原句 |
|----------|----------|------------------|--------------|----------|----------|
| 炸出 | 4 | 发布 | 5 | positive | "OpenAI 又炸出新模型" |
| 锤 | 3 | 批评 | 5 | negative | "网友把这家公司锤上热搜" |

按频率排序，取 top 20-30 → 写入 `language_style.power_verbs`（每条带 `example`）。

#### 4.2 语气色板 → `tone_palette`

语气档位库（不是每个作者都有 5 档，找出该作者实际用的几档）：

| 语气档位 | 判断特征 |
|----------|----------|
| 正经/严肃 | 完整句、书面语、引用数据 |
| 口语/轻松 | 缩略语、语气词（嘛/呗/啊）、短句 |
| 调侃/戏谑 | 自创词、引号反讽、"doge" 类标记 |
| 震惊/感叹 | 感叹号、"我勒个""什么？！"、加粗 |
| 诗意/升华 | 排比、意象、金句、哲理 |
| 学术/专业 | 术语密集、论文式表达 |
| 煽情/热血 | 排比递进、呼吁行动、民族自豪 |
| 冷峻/克制 | 短句、不带情绪词、留白 |

输出：
- 实际使用的几档 + 各档占比 → `tone_palette` 列表
- 切换规律 → `tone_transitions`
- 禁区档位 → 进 `forbidden`

#### 4.3 标点功能 → `punctuation_rules`

| 标点 | 需要观察的功能 |
|------|---------------|
| 加粗 | 信息锚点 / 情绪强调 / 品牌高亮 |
| 引号「」/"" | 引用原话 / 反讽 / 概念高亮 |
| 破折号—— | 解释补充 / 制造悬念 / 语气延伸 |
| 省略号…… | 犹豫 / 留白 / 省略 |
| 多问号？？？ | 真提问 / 情绪外化 |
| 感叹号！ | 使用频率、是否克制 |

每个标点记录 `function` + `density`（high/mid/low）+ 至少 1 个 example。

#### 4.4 口头禅 → `signature_phrases`

记录所有反复出现的短语 / 句式：
- 转折连接词（"这不，""谁曾想，""但问题来了，"）
- 评价短语（"怎么说呢""不得不说""属实""绝了"）
- 情绪词（"炸""绝""顶""离谱"）
- 开头短语（"划重点""先说结论"）
- 自创词 / 昵称（同时进 `custom_vocabulary`）

按出现频率排序，标注每个表达出现的典型语境 → `context` 字段。

#### 4.5 技术 / 抽象概念处理 → `technical_concept_handling`

仅当样本涉及技术 / 抽象内容时填：
- 是直写专业术语，还是必配类比？
- 类比的偏好来源（日常生活 / 游戏 / 影视 / 军事…）
- 给一个最典型的样本例

#### 4.6 自创词典 → `custom_vocabulary`

列出作者的自创词 / 昵称（粉丝称呼、产品昵称、编辑部自称等），逐个解释。

### 维度五：结尾模式 → `ending_craft`

#### 结尾类型库

| 结尾类型 | 特征 | 效果 |
|----------|------|------|
| one_more_thing | 文末彩蛋 / 延伸信息 | 训练完读 |
| poetic_summary | 排比 / 意象 / 升华 | 情绪高峰收尾 |
| open_question | 反问 / 留白 | 引发讨论 |
| cta | "试试看""链接在这" | 转化 / 互动 |
| summary | 一段话概括全文 | 信息闭合 |

统计各类型占比 → `ending_type_distribution`，提取前 2-3 名 → `preferred_endings`，每个写"模板 + 样本例" → `ending_templates`。

如果存在固定 CTA（如"点赞 + 关注"段），完整摘录 → `fixed_cta_text`。

## 4. 场景增量维度库

下面这些维度**只在对应场景启用**。在 `style_profile.yaml` 中放到 `scene_extras.[场景名]` 下。

### 4.1 公众号

```yaml
scene_extras:
  公众号:
    has_brand_header: bool          # 是否有固定版头
    has_brand_footer: bool          # 是否有固定版尾
    community_naming:               # 社群命名体系
      reader: 量子位朋友
      editor: 量子君
    fixed_sections: [一线, 报道]    # 固定栏目名
    cta_position: 文末固定 | 中插 | 无
    article_anatomy: [版头, 导语, 正文, 标题分割, 结语, CTA, 版尾]  # 该号的标准结构
```

### 4.2 知乎

```yaml
scene_extras:
  知乎:
    answer_opening_strategy: [先抛结论, 立场鲜明, 资历铺垫, 故事场景]
    credential_display: high | mid | low   # 答主是否爱秀背景/title
    debate_posture: 引战 | 调和 | 中立     # 对立观点的姿态
    formatting:
      bold_heavy: bool                     # 知乎答案普遍重度加粗
      uses_lists: bool                     # 偏好列表化
      uses_image_meme: bool                # 表情包频率
    answer_length_strategy: 长答堆料 | 短答精华 | 看题选择
```

### 4.3 小红书

```yaml
scene_extras:
  小红书:
    emoji_density: high | mid | low
    emoji_typical: [✨, 💡, 🔥, 🎀]
    tag_strategy: 文末密集 | 标题嵌入 | 段中点缀
```

```yaml
    hedging_density: high | mid | low      # "可能""或许""一般而言"等保留语
```

### 4.7 个人散文

```yaml

  个人散文:
    imagery_density: high | mid | low
    sensory_distribution: { 视觉: 0.4, 听觉: 0.2, 触觉: 0.2, 嗅味觉: 0.2 }
    rhythm_preference: 缓慢沉静 | 急促跳跃 | 长短交错
    first_person_density: very high | high | mid
```

### 4.8 新维度怎么加

如果你发现样本平台不在上述清单（例如：B 站文章、Newsletter、Substack、医美点评类、Reddit），请：
1. 在档案 `scene_extras` 下新增对应 key
2. 在本文档第 4 节加一个子节
3. 写入维度清单 + 每个字段的判断依据

不要硬把新场景塞进现有 key。

## 5. 数据采集模板

精读时使用以下表格记录每篇文章的关键数据：

```markdown
| 序号 | 文件名 | 类型 | 字数 | 段落数 | 极短句数 | 开篇钩子 | 结尾类型 | 引用数 | 图片数 |
|------|--------|------|------|--------|----------|----------|----------|--------|--------|
| 001 | | | | | | | | | |
| 002 | | | | | | | | | |
```

完成后能快速看出：
- 哪种类型的文章最多 → 选题偏好（写入分析报告"内容选题矩阵"，但**不进档案**——档案只记风格不记选题）
- 极短句使用是否稳定 → 节奏一致性
- 引用密度是否均匀 → 信源策略

## 6. 语气色板构建方法

### 步骤

1. 选 3 篇不同类型的文章
2. 逐段标注语气档位（用色标或字母 A/B/C... 标注）
3. 画出语气变化曲线：横轴=段落序号，纵轴=语气档位
4. 寻找规律：
   - 开篇通常在哪个档位？
   - 中间如何交替？
   - 结尾通常升到哪个档位？
   - 哪些档位从不出现？（禁区）
   - 哪些档位转换最频繁？（特色）

### 输出（直接进 `language_style.tone_palette` 和 `tone_transitions`）

```yaml
tone_palette:
  - tone: 正经
    ratio: 0.3
    features: 完整句、术语
    typical_context: 给数据/讲技术原理时
  - tone: 调侃
    ratio: 0.5
    features: 自创词、引号反讽
    typical_context: 评价当事人或行业现象时

tone_transitions:
  - "开篇震惊 → 中段降到正经讲事实 → 结尾回到调侃"
```

## 7. 动词分析方法

### 为什么动词最敏感

同一件事 "公司发布了新产品"，不同作者的动词选择完全不同：
- 量子位："炸出"新产品
- 36 氪："推出"新产品
- 官方通稿："发布"新产品
- 个人博客："demo 了"新产品

动词选择直接决定文章的能量密度和情感温度。**它是区分风格最敏感的指标**。

### 采集方法

1. 精读时标注所有**非通用动词**（排除"是""有""做""用"等基础动词）
2. 特别关注替代了常见中性词的动词（如"锤"替代"批评"）
3. 记录动词出现的语境（正面 / 负面 / 中性事件）

### 输出（直接进 `language_style.power_verbs`）

```yaml
power_verbs:
  - verb: 锤
    replaces: 批评
    intensity: 5
    polarity: negative
    example: "网友直接把他锤上热搜"
  - verb: 炸出
    replaces: 发布
    intensity: 5
    polarity: positive
    example: "OpenAI 又炸出一个新模型"
```

至少 20 条；不到 20 条说明该作者动词偏中性，写入 `notes` 说明。

## 8. 节奏可视化方法

取一篇典型文章，对每一段标注段落类型，然后以序列形式展示：

```
段落 01: L (信息段，3句话)
段落 02: L (信息段，2句话)
段落 03: S (极短句："全网炸锅。")
段落 04: I (图片)
段落 05: S (极短句+转折："但为时已晚。")
段落 06: L (信息段，3句话)
段落 07: Q (引用块)
段落 08: L (信息段，2句话)
段落 09: S (极短句："绝了。")
```

从序列中提炼出节奏公式（写入 `rhythm.rhythm_pattern`）。

不同作者节奏差异很大：
- 高密度短段 + 频繁极短句 → 阅读节奏快（典型：科技自媒体）
- 长段为主，节奏平稳 → 传统媒体
- 纯长段堆砌，无明显节奏变化 → 学术 / 部分严肃博客
- 极短行 + emoji 切割 → 小红书

## 10. 从分析到风格档案的转化路径

分析报告的各章节直接映射到 `style_profile.yaml` 字段。映射表：

| 分析报告章节 | 对应 yaml 字段 |
|-------------|---------------|
| 综合风格画像 | `portrait` |
| 标题术拆解 | `title_craft.*` |
| 开篇手法精拆 | `opening_craft.*` |
| 段落节奏与结构 | `rhythm.*` |
| 动词选择 | `language_style.power_verbs` |
| 语气色板 | `language_style.tone_palette`, `tone_transitions` |
| 标点用法 | `language_style.punctuation_rules` |
| 口头禅与惯用表达 | `language_style.signature_phrases` |
| 自创词典 | `language_style.custom_vocabulary` |
| 结尾模式 | `ending_craft.*` |
| 品牌辨识度（公众号） | `scene_extras.公众号.*` |
| 知乎特有维度 | `scene_extras.知乎.*` |
| 小红书特有维度 | `scene_extras.小红书.*` |
| 禁区清单 | `forbidden` |

### 转化规则

1. **可量化的部分（占比、频率、字数）必须真的数过**——不要拍脑袋写
2. **每个 example 字段都必须来自真实样本原文**——不能编
3. **没观察到的字段留空（删 key）**——不要硬填默认值
4. **比例字段加起来 ≈ 1**（`hook_distribution` / `tone_palette.ratio` / `ending_type_distribution`）
5. **数字与样本量匹配**：样本只有 5 篇时，不要写 `power_verbs` 30 条——观察不到那么多

### 档案生成时机

完成第三步（七维分析）后，**直接同步写出 yaml 档案**，不要等到报告全写完——这样能保证两份产物字段一致。
