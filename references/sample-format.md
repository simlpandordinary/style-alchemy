# 归一化样本格式（Normalized Sample Format）

> 所有分析维度都在"归一化样本"之上工作。无论用户给的原始素材是 md/txt/html/docx/pdf，统一先转成本格式落到 `samples_normalized/` 再分析。

---

## 1. 文件命名

```
samples_normalized/
  001-标题前20字.md
  002-标题前20字.md
  ...
```

- 序号 3 位补零（最多支持 999 篇）
- 序号后接短横线 + 原标题前 20 字（去掉非法字符 `/ \ : * ? " < > |`）
- 全部 `.md` 扩展名
- UTF-8 编码，无 BOM

## 2. 文件结构

每个文件 = YAML frontmatter + 正文 Markdown。

```markdown
---
title: 文章完整标题
author: 作者名 / 账号名 / 未知
platform: 公众号 | 知乎 | 小红书 | 微博 | Twitter/X | 博客 | 学术期刊 | 个人散文 | 新闻媒体 | 其他
url: https://...                # 可空
publish_date: 2024-03-15         # YYYY-MM-DD，可空
word_count: 1234                 # 整数，由 normalize 脚本自动算
source_file: original/xxx.html   # 相对路径，溯源用
language: zh | en | mixed        # 默认 zh
content_type: 争议热点 | 突发新闻 | 人物稿 | 产品技术 | 深度长文 | 访谈对话 | 快讯短消息 | 观点评论 | 个人感悟 | 其他   # 可空，分析阶段会自动填
tags: [tag1, tag2]               # 可空
---

# 标题

正文段落 1。

正文段落 2。

> 引用块

![图片说明](image-placeholder)

- 列表项 1
- 列表项 2

...
```

## 3. 正文规范

| 元素 | 处理方式 |
|------|---------|
| 标题 | 用 `#`（一级标题），保留原标题 |
| 小标题 | `##` `###` 保留层级 |
| 段落 | 段间空一行 |
| 引用 | `> ` 前缀，保留 |
| 列表 | `- ` 或 `1.`，保留 |
| 加粗 | `**xxx**` 保留（这是关键风格信号） |
| 引号 | 中文引号 `「」""` 保留原貌（标点风格信号） |
| 图片 | 转为 `![描述](image-placeholder)` 占位，**不需要下载实图**，只保留位置和说明文字 |
| 视频/音频 | `[视频]` 或 `[音频]` 占位 |
| 链接 | `[文字](url)` 保留 |
| 代码块 | ` ``` ` 保留 |
| 表格 | Markdown 表格保留 |
| HTML 标签 | 全部 strip 掉（除上述对应物） |
| 多余空行 | 压缩成最多 1 个空行 |
| 行尾空格/制表符 | 去掉 |

## 4. 必须保留的"风格信号"

下列元素不能被归一化抹掉，它们是后续分析的核心数据：

- **极短句独立成段**（"绝了。" "全网炸锅。"）— 段间空行必须保留
- **加粗用法**（信息锚点 / 情绪强调 / 品牌高亮）
- **标点风格**（`！！！` `？？？` `——` `……` `「」` `""` 全部原样）
- **emoji 和颜文字**（小红书、Twitter 关键风格）
- **图片位置**（用 placeholder 占位，但顺序不能丢，这是节奏分析的依据）
- **段落顺序**（绝不要重排）

## 5. 必须丢掉的噪音

- 公众号底部"长按关注"图、二维码、广告
- "点赞、在看、转发"等固定 CTA 区块（如果能识别）— 这些应该单独抽取到 frontmatter 的 `tags`，避免污染正文统计
- 评论区、推荐文章卡片
- 网页导航、页脚、版权声明
- 微信/小红书 app 顶部状态栏文字（如果是截图 OCR 来的）
- 重复出现的固定版头/版尾（如果是公众号有，先保留第一篇做风格分析用，其他篇可去掉）

## 6. 不确定时的取舍

| 情况 | 取舍 |
|------|------|
| 不确定 frontmatter 某字段（如 platform、author） | 设为 `未知`，不要瞎猜 |
| 不确定一段是正文还是噪音 | 保留 |
| OCR 来的样本有错别字 | 保留原样，不要"修复"——错别字可能是风格信号 |
| 多个段落连在一起没换行（粘贴常见） | 按句号/感叹号/问号尝试切分，但宁可保守不切，也不要错切 |

## 7. 示例

**原始 HTML 片段**（公众号导出）：
```html
<p><strong>OpenAI收购Astral，</strong>Python包管理神器uv现在姓O了。</p>
<p>全网炸锅。</p>
<p><img src="xxx.jpg" alt="收购公告截图"/></p>
<p>怎么说呢，这事属实有点突然。</p>
```

**归一化后**：
```markdown
---
title: OpenAI收购Astral，Python包管理神器uv现在姓O了
author: 量子位
platform: 公众号
url: https://mp.weixin.qq.com/s/xxx
publish_date: 2025-02-19
word_count: 856
source_file: original/openai-astral.html
language: zh
content_type: 突发新闻
---

# OpenAI收购Astral，Python包管理神器uv现在姓O了

**OpenAI收购Astral，**Python包管理神器uv现在姓O了。

全网炸锅。

![收购公告截图](image-placeholder)

怎么说呢，这事属实有点突然。
```

注意：
- 加粗保留了（虽然加粗范围跨了一个逗号）
- 极短句"全网炸锅。"独立成段保留
- 图片转 placeholder 但位置保留
- "怎么说呢"这种口头禅完整保留
